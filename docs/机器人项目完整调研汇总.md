## 2. 目前的决策建议

**值得探索，定位为“机器人应用、课程、内容与本地交付”，首轮以 SO-101 / XLeRobot 生态建立一个能重复演示和收费验证的技能。**

当前优先顺序：

1. **单臂固定工位的 AI 明信片绘画**：先验证画质、总耗时、稳定性和付费意愿，适合学校与文旅复用。
2. **标准轻物配单与交付**：云南花茶主题的固定格位取放，可作为教学或第二个互动任务。
3. **双臂和两站移动**：等单工位技能可靠、客户确认移动价值后再加入。
4. **景区常驻自主零售**：优先与成熟具身公司洽谈指定场景的完整方案，不能用低价开源 BOM 推导全年无人值守能力。

这是建议排序，用户尚未最终锁定采购型号、试点客户或商品定价。绘画是后续新增的优先方向，并不抹去前面配单场景的研究价值。

原版 Mobile ALOHA 主要用于学习全身遥操作、数据采集、模仿学习与任务评估方法。其论文约 3.2 万美元的硬件成本，以及国内若干 18.8–24 万元科研总成采购样本，都超过当前首轮预算。[Mobile ALOHA](https://mobile-aloha.github.io/)、[郑大验收](https://www7.zzu.edu.cn/ztb/info/1136/19958.htm)

## 3. OmArm Zero 与低成本抓取

### 能力与适用场景

| 项目 | 前期核查结果 |
|---|---|
| 结构 | 5 个机械臂运动关节＋夹爪，共 6 个执行器 |
| 驱动 | 3×MG996R＋3×SG90；ESP32＋PCA9685 |
| 最大臂展 | 作者标称 303 mm |
| 负载 | 作者标称 100 g、峰值 150 g，受肩部弹簧与姿态影响，未独立测量 |
| 视觉示例 | 电脑运行视觉、坐标转换与 ROS 2；抓取贴 ArUco 标签的静止轻物 |
| 示例工作区 | 作者配置下，距基座约 150–190 mm 的俯视抓取区域 |
| 适合用途 | 机械装配、PWM 舵机标定、ESP32 网页控制、轻物抓放与视觉坐标教学 |

来源：[项目仓库](https://github.com/omartronics/OmArm-Zero)、[装配指南](https://omartronics.com/omarm-zero-build-5-dof-robotic-arm-esp32-web-control/)、[视觉教程](https://omartronics.com/computer-vision-pick-and-place-robot-arm/)。

**力矩与负载的关系**：关节需要克服物体、夹爪和各段手臂产生的力矩。简化静态物体力矩为 `τ = m × g × r`，但不能忽略手臂自重、动态加速、温升和结构变形。不能把多个舵机堵转力矩相加得到抓取重量，也不能从商品标题的“kg”推导整臂承重。OmArm 使用的 MG996R/SG90 存在供应商规格差异，本次不为所有替代件给出统一保证力矩。

### 开源与采购限制

固件/网页代码为 MIT；CAD、打印文件和装配包另行出售，前期页面价为 €14.90，许可涉及个人非商业用途。群体教学、公司使用、售卖打印件等不能仅凭固件 MIT 推定已获许可。[CAD 包](https://omartronics.com/product/omarm-zero-6dof-esp32-robotic-arm/)、[许可条件](https://omartronics.com/license/)

2026-10-01 已列候选标价：基础版 **¥302.91 部分小计**，视觉版 **¥343.91 部分小计**。尚缺附件、部分紧固件、相机支架、运费、CAD 人民币实付等，也包含未确认适配的替代型号。**这些均不是完整到手价**；当时 ¥500–650 只是准备金估计。

### 必须保留的工程细节

- 已核查版本的 J1–J6 实际通道为 `0、3、4、7、8、11`，不能照 README 的连续通道号接线。
- 网页版本使用 LittleFS 固件及 `data` 资源；串口版不能当作相同入口。
- 接线图与 README 的 ESP32 针数描述不同，应按 GPIO 编号和实物核对。
- 6806ZZ 是 30×42×7 mm，不能用 686ZZ 替代。
- PWM 软件角度是命令值，不能当成外部关节位置测量。
- 舵机电源独立配电；逻辑供电与舵机供电区分，先空载标定再装连杆。

完整 BOM 规格、历史商品链接和固件问题见 [低成本机械臂及 OmArm 原稿](多轴机械臂抓取开源项目调研-2026-10-01.md)。

## 6. XLeRobot 与 Mobile ALOHA 深度比较

| 维度 | XLeRobot | 原版 Mobile ALOHA |
|---|---|---|
| 主体 | 双 SO-101＋轮式底盘 | 双 ViperX 300 执行臂＋轮式底盘 |
| 手臂自由度 | 每臂 5 运动关节＋夹爪 | 每臂 6 运动关节＋夹爪 |
| 基础成本口径 | 作者约 $660 / ¥3999，不含所有打印、工具、运税等 | 论文约 $32,000 的当时硬件配置 |
| 主要学习软件 | LeRobot 生态、ACT、SmolVLA、pi0.5 等路线 | 全身遥操作、ACT++ 等模仿学习 |
| 首轮价值 | 教学、展示、数采、轻物任务 | 学习系统设计与评估方法 |
| 主要风险 | 舵机与结构精度、软件分支、维护与任务稳定性 | 高预算、原版臂供应变化、任务数据与系统复现 |

来源：[XLeRobot](https://github.com/Vector-Wangel/XLeRobot)、[Mobile ALOHA 论文](https://mobile-aloha.github.io/resources/mobile-aloha.pdf)。

### 力矩、负载与自由度

XLeRobot 原 0.3 三全向轮 BOM 使用 17 个执行器：双臂 12、轮 3、头 2。12 V STS3215 的 30 kg·cm 为堵转力矩，约 2.94 N·m，不是整臂负载。作者给过单臂约 600–1000 g 的范围，但未核到统一姿态、伸展、温升和持续时间的负载曲线。前期优先用 20–50 g 刚性道具验证；更高重量另做测试。[BOM](https://xlerobot.readthedocs.io/en/latest/hardware/getting_started/material.html)

单臂六个电机包含夹爪，不能理解为六个独立空间姿态关节。绘画时应只约束需要的笔尖位置与笔轴方向，并验证小画幅可达性。

### 自主能力与论文结果

XLeRobot 作者明确说明，0.3 家务展示中的多数任务为 Joy-Con 遥操作。已有学习教程不代表所有视频均为自主。双臂 SmolVLA 示例使用 12 维动作，不能据此推导底盘也已学会自主导航。[遥操作](https://xlerobot.readthedocs.io/en/latest/software/getting_started/XLeRobot_teleop.html)、[SmolVLA](https://xlerobot.readthedocs.io/en/latest/software/getting_started/VLA_smol.html)

Mobile ALOHA 论文联合训练结果：擦拭/电梯 95%，收锅 85%，冲锅/推椅 80%，这些各测试 20 次；炒虾 40%，仅测试 5 次。整餐演示在作者页面归入遥操作。它证明具体任务可学习，不能推导为任意环境通用家务能力。[论文](https://mobile-aloha.github.io/resources/mobile-aloha.pdf)

前期核查 ViperX 300 S 产品页已标停产；复刻原版需要确认替代方案。国产臂改变运动学、动作空间、相机与夹爪后，应称方法复现，并重做数据和评估。[产品页](https://www.trossenrobotics.com/viperx-300)

## 8. XLeRobot 的完整技术路径

### 系统分层

```text
任务输入：文字／语音／按钮／遥操作
                  ↓
任务决策：Agent 选择下一项技能
                  ↓
技能执行：移动工具／确定轨迹／训练后的操作策略
                  ↓
运动控制：坐标转换、逆运动学、限位、轨迹插值
                  ↓
设备驱动：LeRobot／Feetech／控制板／舵机
                  ↓
物理动作：手臂、夹爪、头部、轮式底盘
                  ↓
反馈：相机、关节状态、执行结果与错误 → 决策或本地恢复
```

该图是系统分层说明；不同官方示例不一定包含所有模块。直接关节控制、训练策略输出关节动作时，也不必每步再经过笛卡尔逆运动学。

### 三条现有路线

| 路线 | 数据/控制链 | 适用目标 |
|---|---|---|
| 遥操作 | 人输入 → 关节或末端命令 → 机械动作 | 首次调试、演示、采集示范 |
| 模仿学习 | 人演示＋相机/状态记录 → ACT/SmolVLA 等训练 → 预测动作 | 特定抓取、放置、双臂技能 |
| Agent 调技能 | 任务＋图像 → 大模型选工具 → 预设或学习技能执行 | 组合“靠近、取物、递交”等步骤 |

官方已有关节控制、末端逆运动学、双臂及视觉跟踪入口。[机械臂示例](https://xlerobot.readthedocs.io/en/latest/software/getting_started/SO101.html)

官方 Agent 教程使用 RoboCrew，示例模型为 Gemini。行驶封装为工具，抓笔记本和递笔记本封装为预训练 ACT 技能；策略可由另一台电脑运行。教程不是 GPT-6 绘画完整成品。更换模型还要核验视觉输入、工具调用和部署条件。[Agent 教程](https://xlerobot.readthedocs.io/en/latest/software/getting_started/LLM_agent.html)

### 计算与版本

基本控制可用已有电脑；训练和较大策略推理按需求使用外部 GPU。不是所有功能都必须 ROS2，也不是所有社区分支都能在 Mac 无修改运行。确定一次可验证组合：硬件版本、LeRobot/XLeRobot commit、依赖、模型、相机配置、校准文件；交付时保留可重装环境。

移动底盘与机械臂要分别调试。先做到“移动到固定站点→精定位→停车操作”，再研究同时移动操作。底座位置误差会影响外部桌面的坐标；画板若在车上，仍要处理车架稳定性和笔尖接触。

### A. Thijs：最接近 XLeRobot 硬件

作者给予 SO-101、相机、画笔与初始锚点，让模型规划约一分钟的动作片段；人在轮次之间及部分执行期间反馈，模型更新自身指令和校准。**一分钟不是整幅作画时间；“越画越好”也没有证明模型权重经过训练。** MCP、具体 SDK、控制频率、力传感器、完整耗时和费用未公开核清。

### B. astra-paints：最清楚的在线模型调用链

```text
主题＋当前画布 PNG → GPT → JSON 笔画（颜色、二维点、完成标记）
      ↑                                      ↓
画布更新 ← 仿真执行 ← 逆运动学、约 2 mm 插值、抬笔落笔
```

每次要求 3–8 条笔画；执行端为两根平面连杆＋升降轴。它的软件画布通过盖色点形成图像，没有模拟实际水分、颜料混合或毛笔接触。因此可以借鉴规划接口，不能把该运动学直接当 SO-101 驱动。[模型源码](https://raw.githubusercontent.com/riyer8/astra-paints/main/agents/astra_agent.py)、[执行源码](https://raw.githubusercontent.com/riyer8/astra-paints/main/agents/base.py)、[运动学](https://raw.githubusercontent.com/riyer8/astra-paints/main/sim/world.py)、[画布](https://raw.githubusercontent.com/riyer8/astra-paints/main/sim/canvas.py)

### C. 画鸽子：笔尖与接触反馈

铅笔预先放在手里，靠摩擦与接触保持；沿九条预描路径绘制，控制器读取模拟器笔尖位置和接触力并修正。作者报告 173 仿真秒、路径误差中位数 0.149 mm；不能套到 SO-101 实机。控制代码与图案衍生素材的许可还需分开。[实验说明](https://raw.githubusercontent.com/dimentary/llm-robotics-playground/main/experiments/dove-drawing/README.md)

### D. WLKATA：确定性线稿执行

README 要求人先生成、下载线稿。代码为灰度/阈值/Canny→轮廓→多边形近似→点组与版面缩放→厂商运动命令。Z 标定靠人工；部分轮廓按点数丢弃或截断，粗黑线可能追成双边线；中断急停分支仍为 TODO。原码不能直接套到 SO-101。[绘画源码](https://github.com/wlkata/WLKATA-AI-Drawing-Extension/blob/main/src/wlkatapython_extensions/drawing/drawing.py)

### 给 XLeRobot 的建议实现

```text
游客主题／照片／姓名
  → 生成简洁构图或线稿
  → SVG／中心线转换与笔画排序
  → 路径预览、数量与长度约束
  → 纸面坐标 → 底座坐标 → 笔尖位姿
  → SO-101 逆运动学、连续轨迹、限位与速度检查
  → 舵机执行
  → 俯视相机复查 → 必要时有限补画或本地暂停
```

这是新工程建议，不是声称 XLeRobot 已带有该技能。可以封装 `observe_canvas`、`preview_drawing`、`draw_strokes`、`lift_pen`、`stop_drawing`；普通函数或 MCP 都可连接，接口形式不能替代运动控制。

首版使用单从臂、固定台面、小画幅、单色圆头笔和弹性防滑笔架。先验证约 60–80 mm 方形区域，该尺寸是起步目标而非实测保证。弹性笔架提供被动顺应，不能宣传为闭环力控。LeRobot 电机零位标定之外，还需纸面位置/高度及笔尖工具偏置标定。换笔长、笔架或移动相机后复核。

**首版不需要先训练 VLA。** 先用确定路径验证机械控制，再接模型个性化生成；取笔、换笔、递卡和双臂协作可作为后续独立技能。

云南师大已有机器人 STEM 活动；云南大学有机器人/无人车教学基础；斗南已有花礼、花艺体验与文旅业态。这是方向与线索，不是本项目订单或独家市场。[云南师大](https://www.ynnu.edu.cn/info/1062/11702.htm)、[云南大学](https://www.ise.ynu.edu.cn/directory/27/)、[斗南业态](https://swt.yn.gov.cn/swxx/202608/t20260810_3733343.html)

本次没有核到昆明 XLeRobot/Mobile ALOHA 同构项目的公开验收与持续营收记录；不能解释成昆明没有此类项目。具体场地以用户现有渠道和能安排试点的对象为先。

### 与具身公司竞争还是合作

XLeRobot 加感知、策略与执行本身就是具身智能载体。真正的选择是自研多少、采购多少、谁为任务结果负责。

- 反复交付课程：开放小平台＋自有内容和本地服务有价值。
- 一次性展会：比较租机带操作员的交付包与自有样机成本。
- 景区每天营业：优先成熟厂家端到端方案，核验值守、补货、维修和结算责任。
- 高端科研：考虑共享、借用、租赁或客户自行买机，你提供集成和课程。

银河官方将本体接口、场景开发包、端到端方案分层；擎天租有文旅/教培入口，但昆明具体轮式双臂型号、价格、押金和开发权限未核清。[银河开发手册](https://developer.galbot.com/?lang=en)、[擎天租](https://www.botshare.com/cn/)

你的可积累资产是云南主题内容、教案、工装、任务数据、控制软件、客户渠道和快速到场服务。纯硬件转售或只靠新奇外形，竞争压力更大。

## 11. 预算、经济测算与阶段验收

### 预算统一口径

以下为支出规划，不是已经拿到的供应商报价。

- **当前绘画验证阶段**：建议桌面首阶段投入上限约 1 万元，复用电脑，先完成一个可靠技能。
- **完整活动/课程 MVP**：前期以 3.5 万元规划，至 5 万元的剩余额度等出现付费信号再释放。
- 上述两者是分阶段关系，**不是 1 万元再额外加 3.5 万元**；前阶段硬件和工作应复用。
- 全部软件与交付外包时需重估工时，不能保证 5 万元足够。

| 完整 MVP 规划项 | 额度 |
|---|---:|
| 需求访谈、场地测量、脚本 | ¥2,000 |
| 主平台、相机、供电、控制器 | ¥9,000 |
| 备件、运输箱、工装、停止机制 | ¥4,000 |
| 软件与稳定化工程 | ¥8,000 |
| 课程/界面/操作文档 | ¥4,000 |
| 试点交通、人员、耗材与算力 | ¥3,000 |
| 预备金 | ¥5,000 |
| **总计** | **¥35,000** |

### 商业算例，不是收益预测

机构活动：假设前期投入 ¥30,000，每场收入 ¥3,000、增量成本 ¥1,500，则单场贡献 ¥1,500，20 场覆盖前期投入；收入降到 ¥2,000 时需 60 场。未包含税、销售管理、坏账及未计机会成本。

游客付费：假设每次 ¥29，物料 ¥8、场地分成 ¥6，单次贡献 ¥15，日运营成本 ¥500，则 30 单/日亏 ¥50，50 单余 ¥250，80 单余 ¥700。对应回收不能忽略淡旺季、停机、税和开发工时。原稿数字用于一般互动商品假设，**并未核实为绘画明信片的实际成本和定价**。

绘画吞吐量：若一单总周期为 5 分钟，理论上限 12 单/小时；换纸、等待和返工继续降低产能。5 分钟只是算术示例，不是已有实测结果。须测模型生成、路径处理、机械绘制和人工操作各阶段用时。

### 建议实施步骤

1. **明确付费任务**：访谈约 5 个已有联系人，争取 2 个具体试点窗口，确认付款主体、现场条件和客户评价标准。
2. **先打通机械基线**：固定单臂，画直线/圆/方框，检查抬落笔、偏移与接触；或固定格位轻物取放。
3. **建立重复性**：绘画先连续 20 张基础图，再对 10 种图案各重复 3 次，完整记录失败、耗时和接管。
4. **接模型与视觉**：保持同一运动执行层，接入个性化构图、预览和有限视觉复查；分别统计生成失败和机械失败。
5. **做真实试点**：至少学校/培训和文旅各一次，记录收费、停留、成交、工作人员工时与恢复时间。
6. **再决定扩展**：客户确实需要时加入两站移动、第二只手或成熟平台合作。

这些可放入约六周计划，但依赖硬件交期、工程人力和场地排期，不是保证工期。

### 避免混用验收门槛

原稿含多个阶段测试：100 次取放/95 次成功属于早期原型目标；200 次完整任务/196 次无需人工完成属于更高阶段建议；绘画的 20 张/30 张为任务专属测试。它们不是同一个验收标准，也不是已达成成绩。

商业继续条件建议：2 个明确付费试点，或 1 个已付款客户＋明确复购；单场贡献为正；第二位操作员可按文档启动、复位和处理故障。停止或缩范围的信号：只有围观没有付款、客户不为移动能力付费、维护工时长期吞掉收入、无法稳定重复。

绘画任务要求：同一笔架和纸张、目标画幅、连续不剪辑绘制、失败记录和总节拍。抓取任务要求：指定重量/尺寸、台面高度、伸展距离、两站路线。不能用供应商其他任务视频替代。

租赁/成熟具身方案分别问：活动包、开发版周/月租、永久购机、指定场景整包。写清操作员、押金、二次开发权限、现场支持、停机责任、退出安排与分成。不要预设厂商会免费投放设备。
