# XLeRobot 双从教程：调研与落地判断

调研日期：2026-10-07。已用提供的访问密码打开飞书教程，读取核心文字章节，并对照当日可访问的官方文档。没有安装软件、连接机器人或执行运动命令。

## 结论

这份教程值得作为 OneRobot 套件的中文装配与入门参考，但目前不能直接视为与最新 LeRobot 配套、可逐条复制运行的完整双臂自主操作手册。硬件说明有实用细节；软件部分存在旧路径、新安装方式、不同底盘示例混用，以及部署示例缺少模型参数的问题。

“双从”应理解为机器人有两条执行任务的 follower 臂。它本身不代表已有自主策略，也不代表必须购买两条 leader 臂：键盘、Xbox、Joy-Con、VR 与实体主臂是不同的操控路线。若选实体双主臂采集，才需要相应双主臂硬件与配置。

用户已于2026-10-07确认：这套是 XLeRobot 0.4 双轮差速、12V版本。后续按双轮和12V供电路线核对；底盘版本和套件电压已由用户确认。本次仍未核验实际电源规格、装配、通电和配套软件版本。如果另配独立主臂，其电压应按该主臂标签单独确认。

对这套硬件：装配优先对应双轮0.4.0章节；Joy-Con 路线对应教程列出的双轮脚本；若采用当前官方插件方案，对应 `lerobot_robot_xlerobot_2wheels` 和 `robot.type=xlerobot_2wheels`。实际参数仍需与锁定的代码版本核对。双轮差速只能通过前后行驶和转向实现平面移动，不能套用三轮全向底盘的横移控制。

## 2. 有用的部分

- 学习顺序合理：先打通一条 SO-101 臂，再扩展双臂、底盘和策略。
- 成品与散件分开处理：厂家称成品已做 ID、波特率、中位设置和遥操作测试。这是教程对其成品的说明，不等于已验证你的实物。
- 提醒校准方向异常会导致撞限位，特别点名从臂3号舵机；第一次动作应逐关节、低幅度观察。
- 明确供电必须匹配7.4V/12V舵机。文中另有7.3V 3A及12V 4A适配器说明，最终按实际舵机标签和套件电源确认，不能仅凭页面示例选电源。
- 厂家给出建议最大负载400g；未提供不同姿态的负载曲线，本次也未实测，不应当作全姿态额定负载。
- 硬件页有结构更新分界：2026年3月3日后购买的肩颈部件按新版装配；说明了不同螺丝长度可能影响横摆运动。
- 采集部分强调固定相机视角、减少丢帧、避免录入大量静止画面。这些直接影响模仿学习效果。

## 3. 需要修正或核对的问题

| 问题 | 已看到的证据 | 对实际操作的影响与处理 |
|---|---|---|
| 安装方式发生变化 | 飞书仍要求复制 model、robots、examples；官方当前英文安装页改为安装 XLeRobot 插件 | 不能把旧复制流程与新目录混用。先锁定 LeRobot、XLeRobot 的版本/提交，再选对应安装方案 |
| 官方中英文页面也不同步 | 当日中文安装页仍写移动文件；英文页写插件安装 | 中文方便理解，实际目录及命令要再与所用代码对应，不能只认 `latest` 或页面标题 |
| 三轮与双轮混用 | Joy-Con 处分别列出三轮及双轮脚本；整机采集示例仍为 `robot.type=xlerobot` | 双轮路线要检查是否使用 `xlerobot_2wheels` 与对应配置；不能直接套三轮底盘映射 |
| “部署”示例不完整 | 示例仍是录制脚本，加 `teleop.type=xlerobot_vr`，没有模型路径 | 该命令不足以证明自主推理。旧版应按其策略推理接口加载 checkpoint；当前官方主线另提供 `lerobot-rollout` |
| 路径、端口、相机均为作者示例 | `/home/tommy`、`/Users/...`、`/dev/right_arm`、相机序列号等混在示例中 | 必须替换并核验。USB插入顺序不能保证设备号永久不变 |
| 深度相机是特定分支方案 | 详细页要求切到 `DepthCameraSupport`，使用专门相机类型 | 本次未核验该分支属于哪个配套仓库、是否仍维护。应先确认来源，再选择分支与驱动；有深度流不代表策略已经利用深度 |
| 不宜固定照搬训练步数 | 基础教程示例有300000步、batch size 8 | 训练量应按数据规模、验证表现和设备调整；没有你的数据集，无法据此预测训练时间或成功率 |
| 清理数据命令会删除内容 | 推理准备示例中有 `rm -rf` | 首次操作直接采用新的评估目录，保留原采集数据与模型，不需要先删除已有目录 |

还有一处术语错误：软件页把 `0.0.0.0` 称为回环接口。它通常表示监听所有本地 IPv4 接口；同机连接可用127.0.0.1，跨机客户端应连接服务器实际局域网 IP。

上述问题是文字/接口层面的审核结果，没有运行对应旧代码，不能断言所有旧示例必然失败。

## 4. 环境和额外硬件判断

飞书基础教程推荐 Ubuntu 22.04、Python 3.12，使用 Miniforge 和 FFmpeg。当前 LeRobot 官方安装页也要求 Python>=3.12，并把硬件、训练、策略依赖分组。飞书的全量依赖安装可以很重；入门应按所选机器人和策略安装所需功能。

你使用的 Mac 可以用于阅读、开发和部分 LeRobot 工作流，但这份教程的 Linux 设备路径、串口权限与蓝牙步骤不能原样搬到 macOS。官方提供 MPS 设备支持；ACT 可在 Apple Silicon 上尝试，是否满足速度仍要按你的 Mac 型号、内存、相机数和数据量验证。不能把 RPent 的 Linux/CUDA 要求泛化为所有 LeRobot 功能都必须使用 NVIDIA。

树莓派、Jetson、RealSense、VR 不是完成第一条机械臂连接的共同必需品。优先使用已有电脑、现有 RGB 相机和一种操控方式。需要更多算力或深度感知时，再依据任务和实测补齐。

YOLO 跟踪只能证明目标检测与机械臂跟随的实现入口，不能等同于自主抓取。ACT 是从演示学动作；SmolVLA等模型也需要适配数据、动作空间和实际任务。通用模型名称不代表你的双臂已经学会任意任务。

## 5. 推荐落地顺序与通过标准

| 阶段 | 操作重点 | 通过标准 |
|---|---|---|
| 0. 核对套件细节 | 已确认0.4双轮差速、12V；继续核对实际电源规格、肩颈结构、预设 ID、总线接线、相机、主臂/手柄配件、计算机 | 一张硬件及端口清单；明确实际供电和厂家预配置情况 |
| 1. 固定软件 | 选择配套提交/版本，保存环境和配置；备份现有校准 | 导入和设备识别正常，版本与教程所选路线对应 |
| 2. 单臂通电 | 固定底盘，先一条从臂；逐关节小幅动作；验证停止 | 方向、范围、夹爪及停止符合预期，无撞限位 |
| 3. 扩展双臂 | 两臂独立识别，记录实际总线/ID；再同步操控 | 只控左臂时右臂不误动，反之亦然；运动范围不互相碰撞 |
| 4. 简单任务采集 | 固定场景与相机，先录几段检查质量，再扩到数十段 | 视频和关节动作对应，无明显丢帧、错误 episode 或相机遮挡 |
| 5. ACT 基线 | 先固定位置的小物体取放，加载实际训练模型 | 用独立评估尝试记录成功次数、失败类型、停止/恢复情况 |
| 6. 整机与更大模型 | 双轮、移动任务、VR、SmolVLA、外部策略服务器按需添加 | 前阶段稳定后逐项引入，避免同时改变相机、模型和底盘 |

这是建议验收路线，不是本次已经完成的测试。对于此前讨论的绘画任务，接通单臂后还需要笔夹、抬落笔、纸面坐标标定和轨迹控制；这份教程没有给出完整绘画方案。
