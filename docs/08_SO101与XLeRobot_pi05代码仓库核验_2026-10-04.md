## 3. 本轮核验后的关键修正

### 单臂适配基座的能力边界

jinnymo 的发布权重位于 [dongyoonkim/so101-pi05-base](https://huggingface.co/dongyoonkim/so101-pi05-base)，数据位于 [对应数据仓库](https://huggingface.co/datasets/dongyoonkim/so101-pi05-base-dataset)。这是域适配基座；状态/动作均为 6 维，包含夹爪。XLeRobot 双臂需要定义两臂动作及标定顺序，底盘还要另定义状态和控制，不能把 6 维输出直接拼接成整机策略。[基座说明](https://github.com/jinnymo/so101-pi05-base)

特别注意：作者的 LoRA 文档明确写明，所列既往 LoRA 实测来自原始 `lerobot/pi05_base`，**尚未训练和评估发布的 SO-101 基座之上的 LoRA**。因此不能声称它已经证明本任务微调效果更好。[LoRA 文档](https://github.com/jinnymo/so101-pi05-base/blob/main/docs/07-lora-finetuning.md)

### 三条技术路线分开建环境

| 路线 | 本次读取的依据 | 接入时需要确认 |
|---|---|---|
| LeRobot 官方 π0.5 | `policy.type=pi05`；文档列出 `lerobot/pi05_base` | 当前 CLI、相机映射、实际 checkpoint 配置与 tokenizer 访问许可 |
| jinnymo / VLASH | README 验证环境使用 LeRobot 0.4.1、固定 VLASH commit；教程读 LeRobot v2.1 数据 | v3 数据先转换；相机键与顺序、缺失相机 mask、动作坐标和统计量一起检查 |
| ljt228 / OpenPI | JAX 双 expert LoRA；SO101Outputs 最终截取 6 维动作 | 配置注册、数据键映射、关节顺序、归一化与策略客户端配套 |

来源：[LeRobot π0.5](https://github.com/huggingface/lerobot/blob/main/docs/source/pi05.mdx)、[jinnymo 环境](https://github.com/jinnymo/so101-pi05-base)、[ljt228 实战](https://github.com/ljt228/pi05-so101-finetune)、[SO-101 变换源码](https://github.com/ljt228/pi05-so101-finetune/blob/main/src/openpi/policies/so101_policy.py)。同名 π0.5 不意味着权重、adapter、配置和归一化文件可直接互换。

### 实战仓库存在 README / 源码差异

ljt228 README 写到 `scripts/train.sh`，本次固定 commit 的文件树没有这个文件，实际有 `scripts/train.py` 和 `scripts/train_pytorch.py`。`config/pi05_so101_lora_finetune.py` 是供训练配置注册使用的片段，引用未在片段中导入的 `LeRobotSO101DataConfig`、`AssetsConfig`，不能直接当独立 Python 脚本运行。实施时先检查 `src/openpi/training/config.py` 中的配置与数据路径，再决定使用哪个入口。[配置片段](https://github.com/ljt228/pi05-so101-finetune/blob/main/config/pi05_so101_lora_finetune.py)

### XLeRobot 双臂分支名需要改正

[XLeRobot π0.5 官方教程](https://xlerobot.readthedocs.io/en/latest/software/getting_started/VLA_pi05.html) 页面显示 `pi05 dual arm` 和 `biso101 training_support`。GitHub 分支查询确认实际名称为 `pi05_dual_arm` 和 `biso101_training_support`。教程仍说明部分改动在社区分支中；可用性需要自己复现，不作为已合入官方主线的承诺。

### 算力数字用于选实验环境

OpenPI README 给出单卡估计：推理 >8 GB、LoRA >22.5 GB、全量微调 >70 GB；这是上游口径，具体相机数量、batch 和后端会改变显存需求。[OpenPI 要求](https://github.com/Physical-Intelligence/openpi#requirements)

jinnymo 的 LoRA 文档记录单相机 24 GB 运行案例，以及双相机同 batch OOM 和 48 GB 运行案例；不能将“24 GB 可用”推广到任意双相机配置。先跑小规模训练并测显存、推理延迟，再按当前算力价格估算。本轮没有刷新云 GPU 报价。[LoRA 显存实测与限制](https://github.com/jinnymo/so101-pi05-base/blob/main/docs/07-lora-finetuning.md)

## 5. 本项目接下来怎样用

1. **绘画 P0**：按 [4 周 MVP 计划](07_AI现场绘画商业MVP_4周计划.md) 完成小画幅轨迹、纸面与笔尖标定、抬笔和停止接口。保留相机观测与执行日志。
2. **单臂辅助操作**：选一个固定工位取卡/递卡任务；先用 LeRobot 完成标定、遥操作、数据录制和回放。保存实际关节顺序、动作单位、相机键、帧率及 calibration 文件。
3. **选择一条 π0.5 路线**：用相同任务数据评估训练和推理，先完成短训练、离线动作检查，再做受控实机测试。jinnymo 和 ljt228 作为候选，效果由本场地数据验证。
4. **单臂稳定后扩双臂**：参考 xuweiwu 配套分支，重新定义双臂状态/动作、相机和数据 schema。底盘移动保持独立调度，直到有移动操作数据与完整评测。
5. **记录可交付证据**：完整任务成功率、耗时、失败类型、人工介入和推理延迟；训练 loss 不能代替这些指标。上述为建议验收项目，本轮没有实测结果。
